# 批量亚马逊商品条码标签工具设计文档

日期：2026-03-29

项目目录：`/Users/patrick/Documents/LabelCreating Project`

## 1. 背景与目标

当前 `Labelcreator` 已经具备单个亚马逊 `FNSKU` 标签的预览与 PDF 导出能力，标签尺寸、条码清晰度、边距和版式规则已经在既有需求中被明确约束。

本次设计的目标不是继续扩展单条标签功能，而是将工具升级为一个适合日常运营场景的“批量标签工作台”，让用户可以直接从 Excel 中整块粘贴多行商品数据，一次性生成多个独立标签 PDF，并统一打包为 ZIP 下载。

本次设计重点服务于“快速批量创建亚马逊商品条码标签”这一核心使用场景。

## 2. 本次范围

本次设计包含以下内容：

- 保留标签预览功能
- 保留 PDF 导出能力
- 新增 Excel 表格整块粘贴的批量输入流程
- 新增批量数据解析、校验、错误提示和逐行检查体验
- 新增多条记录生成多个独立 PDF，并统一打包为 ZIP 下载
- 新增 `产品中文名称` 字段，仅用于文件命名，不显示在标签中
- 将 `Store Name` 标准化为受控选项
- 将 `Condition` 固定为 `NEW`，不再要求用户输入

本次设计不包含以下内容：

- PNG 导出
- 浏览器打印功能
- CSV 文件上传
- Excel 文件直接上传
- 复杂表格编辑器能力
- 合并为单个总 PDF 的导出模式
- Unicode PDF 字体增强

## 3. 用户场景

目标用户在 Excel 中维护一批待创建标签的商品数据。用户希望：

- 不需要逐条录入
- 不需要逐个命名导出文件
- 可以粘贴后快速发现错误数据
- 可以在导出前逐条检查标签预览
- 导出结果直接是一个 ZIP，内部每个 PDF 都已经按规则命名完成

典型流程如下：

1. 用户打开网页
2. 用户查看固定列顺序提示
3. 用户从 Excel 中复制多行商品数据
4. 用户将数据整块粘贴到网页中
5. 页面自动解析为多条标签记录
6. 页面展示数据表格和当前选中行的标签预览
7. 如果存在错误，页面提示错误并阻止整批导出
8. 用户逐条检查预览
9. 所有记录通过校验后，用户点击导出
10. 页面生成多个独立 PDF，并统一打包成 ZIP 下载

## 4. 页面结构

页面保持单页工具形态，延续“左侧数据操作，右侧实时预览”的思路，但升级为适合批量处理的布局。

### 4.1 顶部操作区

顶部操作区包含以下元素：

- 固定列顺序说明
- 批量粘贴输入区
- `清空数据` 按钮
- `校验数据` 按钮
- `导出 ZIP` 按钮
- 当前解析结果和错误摘要提示

固定列顺序提示必须明确告诉用户，粘贴内容不带表头，并且必须严格按下面顺序排列：

`SKU | FNSKU | Manufacture SKU | 产品中文名称 | Item Name | Store Name`

### 4.2 数据表格区

页面中部展示解析后的记录表格。表格不是完整电子表格编辑器，而是“可检查、可定位、可选中”的数据检查区，承担以下职责：

- 展示每一条解析后的记录
- 标记错误行
- 显示错误字段和错误原因
- 支持点击某一行后切换右侧预览
- 支持默认选中第一条记录

### 4.3 单条标签预览区

右侧始终只展示“当前选中行”的标签预览。预览区需支持：

- 默认展示第一条记录
- 支持 `上一条 / 下一条` 切换
- 支持点击左侧表格某一行后同步切换
- 始终使用正式导出版式进行渲染，避免预览与导出不一致

## 5. 输入模型

### 5.1 粘贴格式

输入来源为 Excel 或其他表格软件复制出的制表符文本。

输入数据不带表头，按固定列顺序解析：

1. `SKU`
2. `FNSKU`
3. `Manufacture SKU`
4. `产品中文名称`
5. `Item Name`
6. `Store Name`

页面应支持一次性粘贴多行。

### 5.2 字段规则

#### `SKU`

- 必填
- 显示在标签中

#### `FNSKU`

- 必填
- 用于生成条码
- 显示在标签中
- 同时参与 PDF 文件命名

#### `Manufacture SKU`

- 必填
- 显示在标签中

#### `产品中文名称`

- 必填
- 不显示在标签中
- 仅用于生成 PDF 文件名

#### `Item Name`

- 必填
- 显示在标签中

#### `Store Name`

- 非空时必须属于以下受控值之一：
  - `NA`
  - `EU`
  - `AU`
  - `Walmart-US`
- 如果为空，则系统自动补为 `NA`
- 显示在标签中
- 同时参与 PDF 文件命名

#### `Condition`

- 不再出现在粘贴输入列中
- 系统内部固定为 `NEW`
- 始终显示在标签中
- 用户不可编辑

## 6. 标签展示规则

标签本身继续沿用既有标签规范，确保与当前单标签版本的版式一致。

必须保留的既有规则包括：

- 标签尺寸为 `6cm x 3cm`
- 所有内容必须位于 `1.5mm` 安全边距内
- 标签最终输出不带边框
- 不显示字段名，只显示字段值
- `Manufacture SKU` 居中
- `FNSKU` 居中
- 条码基于 `FNSKU` 生成
- `Item Name` 位于条码文字下方
- `SKU` 位于 `Item Name` 下方
- `Condition` 位于左下角，值固定为 `NEW`
- `Store Name` 位于右下角
- 字体延续 `Arial / Helvetica` 风格
- 导出文本使用 regular weight

`产品中文名称` 不允许进入标签内容，只保留在导出命名逻辑中。

## 7. 解析与状态管理

页面内部应将批量处理拆成清晰的状态阶段：

1. 原始粘贴文本
2. 解析后的记录数组
3. 每条记录的校验结果
4. 当前选中记录索引
5. 是否允许导出
6. 导出进行中状态

每条记录建议在内部统一为标准对象，至少包含：

- `sku`
- `fnsku`
- `manufactureSku`
- `productChineseName`
- `itemName`
- `storeName`
- `condition`
- `errors`

其中 `condition` 始终在标准化阶段直接写为 `NEW`。

## 8. 校验规则

导出采用“整批阻止”策略。只要任意一行存在错误，整批 `导出 ZIP` 都不可执行。

### 8.1 必填校验

以下字段必须存在且不能为空：

- `SKU`
- `FNSKU`
- `Manufacture SKU`
- `产品中文名称`
- `Item Name`

### 8.2 `Store Name` 校验

- 如果为空，自动补 `NA`
- 如果非空但不属于允许值列表，则该行报错
- 只要存在非法 `Store Name`，整批阻止导出

### 8.3 列数量校验

- 如果某一行的列数少于预期列数，应标记为格式错误
- 如果某一行出现明显多余列，也应标记为格式错误
- 错误提示必须定位到具体行

### 8.4 空行处理

- 纯空行应在解析时忽略
- 含有残留制表符但无有效内容的异常空行，应作为格式异常处理或在标准化阶段清理，最终表现必须稳定且可预期

### 8.5 错误呈现

错误提示必须做到：

- 明确指出第几行出错
- 明确指出哪个字段出错
- 明确说明错误原因
- 在表格中高亮错误行

## 9. 预览联动规则

预览区与数据区必须保持一致：

- 首次解析成功后默认展示第一条记录
- 点击表格任意一行后，预览切换到该行
- 点击 `上一条 / 下一条` 后，表格选中状态同步变化
- 即使当前行有错误，仍可预览其标签，以便用户检查问题来源

预览展示使用正式标签渲染逻辑，而不是简化草图，避免用户在导出时看到与预览不一致的版式。

## 10. 导出设计

### 10.1 导出模式

本次只支持一种导出方式：

- 为每条记录生成一个独立 PDF
- 将所有 PDF 打包为一个 ZIP 下载

不支持：

- 单个总 PDF
- 多文件逐个浏览器弹出下载

### 10.2 文件命名规则

每个 PDF 文件名固定为：

`【标签】--产品中文名称--Store Name--FNSKU.pdf`

示例：

`【标签】--方形柚木浴室凳--NA--X001ABCDEF.pdf`

### 10.3 文件名安全处理

如果 `产品中文名称`、`Store Name` 或 `FNSKU` 中含有操作系统文件名不允许的字符，系统应在导出阶段将其替换为安全字符，以确保下载成功。

该安全替换仅影响实际导出的文件名，不改变页面中展示的原始业务数据。

### 10.4 导出门槛

`导出 ZIP` 仅在以下条件全部满足时可用：

- 至少存在一条解析成功的记录
- 所有记录都通过校验
- 当前没有导出任务正在执行

### 10.5 ZIP 内容一致性

ZIP 内文件数量必须与当前通过校验的记录数量完全一致。

## 11. 技术实现建议

继续保持“单文件、本地可运行、无远程依赖”的方向，避免引入依赖安装和在线资源问题。

建议在实现上拆成以下职责模块：

### 11.1 粘贴解析模块

负责：

- 读取批量粘贴文本
- 按制表符和换行拆分数据
- 生成结构化记录
- 自动补默认值

### 11.2 校验模块

负责：

- 检查必填字段
- 检查列数
- 检查 `Store Name` 合法性
- 汇总错误信息
- 计算是否允许整批导出

### 11.3 表格状态模块

负责：

- 存储解析后的记录
- 存储当前选中行
- 维护错误状态
- 维护导出按钮状态

### 11.4 标签渲染模块

负责：

- 渲染右侧单条预览
- 复用正式导出所需的标签排版规则
- 保持条码清晰度和现有视觉规范

### 11.5 导出模块

负责：

- 为每条记录生成独立 PDF
- 按命名规则生成文件名
- 将多个 PDF 打包成 ZIP
- 触发浏览器下载

## 12. 交互细节建议

为了保证高频批量使用时足够顺手，建议补充以下交互细节：

- 粘贴后自动解析，无需再次点击“导入”
- `校验数据` 按钮可用于用户手动重新检查
- 错误摘要区显示总记录数、错误记录数、可导出状态
- 当没有数据时，预览区显示空状态提示
- 当导出进行中时，按钮进入禁用状态并显示进度提示
- 清空数据后，同时清空表格、预览和错误提示

## 13. 验收标准

本次设计的实现完成后，至少应满足以下验收条件：

- 可正确粘贴 1 行数据并生成标签记录
- 可正确粘贴多行数据并生成多条记录
- 粘贴顺序错误或列数不对时能准确提示
- `Store Name` 为空时自动补为 `NA`
- `Store Name` 非法值时整批阻止导出
- `Condition` 无需输入且始终为 `NEW`
- 右侧预览默认显示第一条，并支持逐行切换
- 点击表格行与预览切换保持同步
- 每条记录生成一个独立 PDF
- ZIP 内 PDF 数量与记录数量一致
- PDF 文件名符合 `【标签】--产品中文名称--Store Name--FNSKU.pdf` 规则
- 标签导出的尺寸、边距、条码清晰度和版式规则与原始标签规范一致

## 14. 非目标与后续扩展

本次设计没有将以下内容纳入首版范围，但可以作为后续迭代方向：

- 直接上传 Excel 文件
- 批量编辑表格单元格
- 导出总 PDF
- 批量生成多份副本
- Unicode PDF 文本支持增强
- 更多站点或店铺标识规则
- 批量模板保存和复用

## 15. 实施结论

本次设计将 `Labelcreator` 从单条标签生成页面升级为“批量标签工作台”，核心策略是：

- 保留既有标签规范与预览能力
- 将输入方式升级为 Excel 整块粘贴
- 通过数据表格和单条预览来实现批量检查
- 通过整批校验来保证导出稳定性
- 通过独立 PDF + ZIP 下载来匹配实际工作流

这套方案兼顾了输入速度、错误可控性和导出效率，适合高频批量创建亚马逊商品条码标签的使用场景。
